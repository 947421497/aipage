# 快速开始指南

## 概述

本指南旨在帮助开发者快速上手一鱼快速构架项目，通过详细的步骤说明和示例讲解，使开发者能够在最短时间内完成开发环境搭建、项目配置和基础功能开发。无论你是刚接触 PHP 框架的新手，还是希望快速了解本框架特性的老手，都能从本指南中获得有价值的信息。指南按照实际操作流程编排，建议按顺序阅读并在本地环境动手实践，以加深对框架的理解。

一鱼快速构架基于 XPHP 框架开发，集成了用户管理、后台管理、配置管理等常用模块，开发者无需从零开始搭建项目框架，可以直接在此基础上进行业务功能开发。框架采用 MVC 架构设计，代码结构清晰，扩展性强，适合快速迭代开发场景。

## 环境准备

### 开发工具选择

进行一鱼快速构架开发需要准备合适的开发工具。首先需要选择一个功能完善的代码编辑器，Visual Studio Code 是目前最流行的选择，其丰富的扩展生态和良好的 PHP 支持使其成为 PHP 开发的首选工具。PHPStorm 是 JetBrains 出品的专业 PHP IDE，提供了深度集成的开发环境，适合大型项目的专业开发。对于数据库管理，可以使用 Navicat、DBeaver 或 phpMyAdmin 等工具，这些工具提供了可视化的数据库操作界面。

版本控制工具 Git 是现代开发的标准配置，通过 Git 可以管理代码版本、协同开发和备份代码。GitHub 或 Gitee 等代码托管平台可以存储项目代码并与团队成员共享。建议开发者熟悉 Git 的基本命令，包括提交、拉取、推送、分支管理等操作。命令行工具也是 PHP 开发者需要熟悉的工具，Windows 系统可以使用 PowerShell 或 Windows Terminal，macOS 和 Linux 系统可以使用系统自带的终端。

### 本地开发环境

本地开发环境的搭建有多种方案可供选择。宝塔面板是可视化的服务器管理面板，不仅适合生产环境部署，也适合本地开发使用，它提供了可视化的 LAMP/LNMP 环境配置、站点管理、数据库管理等功能。PHPStudy 是另一个常用的本地开发环境集成包，界面简洁，操作简单，适合快速搭建开发环境。Docker 容器化部署方案适合有一定容器技术基础的开发者，通过 Dockerfile 可以快速构建统一的开发环境，确保团队成员使用相同的配置。

无论选择哪种方案，都需要确保满足框架的环境要求。PHP 版本需要在 8.1 到 8.5 之间，MySQL 版本需要在 5.6 到 8.0 之间。安装完成后，可以通过命令行验证 PHP 版本：打开终端或命令提示符，输入 php -v 查看输出的 PHP 版本号。输入 php -m 可以查看已安装的 PHP 扩展列表，确认 json、pdo、mbstring、gd 等必要扩展已安装。

### 必要扩展验证

验证 PHP 扩展是否完整安装是环境准备的重要步骤。直接在命令行执行 php -m 命令会列出所有已安装的扩展，检查输出中是否包含以下必要扩展：json 扩展用于 JSON 数据编解码；pdo 扩展用于数据库连接；mbstring 扩展用于中文字符串处理；gd 扩展用于图片处理；openssl 扩展用于加密通信；curl 扩展用于 HTTP 请求。如果某些扩展缺失，需要在 PHP 配置中启用对应扩展。

不同环境启用扩展的方法有所不同。宝塔面板用户在软件管理中找到对应 PHP 版本，点击设置按钮，在配置文件中添加扩展或在扩展列表中勾选要启用的扩展。PHPStudy 用户在环境设置中找到 PHP 设置，勾选需要的扩展后保存并重启服务。编译安装的 PHP 需要重新编译或通过 pecl 安装对应扩展。

## 项目安装

### 下载与解压

获取一鱼快速构架安装包有多种途径。可以从框架官方网站下载最新的稳定版本安装包，也可以从 GitHub 或 Gitee 等代码托管平台克隆或下载项目代码。使用 Git 克隆项目可以获得完整的版本历史记录，也便于后续接收框架更新。

下载完成后，将安装包解压到指定的网站目录。在宝塔面板中创建的站点，网站目录通常位于/www/wwwroot/你的域名/目录下。使用 PHPStudy 时，网站目录位于安装目录下的WWW子目录中。确保网站目录指向 public 子目录，这是 Web 服务器的根目录，包含入口文件和公共资源。

### 数据库配置

配置数据库连接是安装过程中的关键步骤。一鱼快速构架支持两种数据库配置方式。第一种是直接编辑配置文件，打开 config/database.php 文件，修改 db_driver（数据库驱动，默认mysql）、db_host（数据库地址，通常为localhost）、db_port（端口号，默认3306）、db_name（数据库名）、db_user（数据库用户名）、db_pass（数据库密码）、db_charset（字符集，默认utf8mb4）、table_prefix（表前缀，默认xphp_）等配置项。第二种是使用环境变量文件，将 env.example.env 重命名为 .env，在文件中配置数据库连接信息。

创建数据库需要在 MySQL 中执行建库语句。使用 phpMyAdmin 工具时，登录后点击新建数据库，输入数据库名称，选择 utf8mb4_general_ci 排序规则，点击创建按钮。使用命令行时，登录 MySQL 后执行 CREATE DATABASE 数据库名 CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci; 命令。确保数据库用户有足够的权限操作该数据库，通常赋予该用户对该数据库的全部权限即可。

### 伪静态配置

伪静态规则使 URL 更加美观，同时是框架路由功能正常工作的基础。不同的 Web 服务器有不同的配置方式。

Nginx 服务器的伪静态配置如下：在宝塔面板中找到对应的站点，点击设置按钮进入站点配置页面，选择伪静态选项卡，粘贴以下规则并保存：

```nginx
location / {
    if (!-e $request_filename) {
        rewrite  ^(.*)$  /index.php/$1  last;
    }
}
```

Apache 服务器需要在 public 目录下的 .htaccess 文件中添加伪静态规则：

```apache
<IfModule mod_rewrite.c>
  Options +FollowSymlinks -Multiviews
  RewriteEngine On
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteRule ^(.*)$ index.php? [L,E=PATH_INFO:$1]
</IfModule>
```

配置完成后，重启 Web 服务器使配置生效。宝塔面板用户可以直接在面板中重启 Nginx 或 Apache 服务，PHPStudy 用户点击重启按钮即可。

### 执行安装向导

完成以上配置后，在浏览器中访问网站域名或服务器 IP，即可看到安装向导页面。安装向导会引导完成以下步骤：第一步是选择备份目录，系统会列出可用的数据库备份文件；第二步是执行SQL文件，系统会按顺序执行备份目录中的SQL脚本，包括删除旧表、创建新表、插入初始数据；第三步是生成install.lock锁定文件，安装完成后系统会自动锁定安装功能，防止重复安装。

安装过程中如遇到问题，首先检查数据库连接配置是否正确，确认数据库服务是否正常运行。查看 runtime 目录是否存在，如不存在需要手动创建并赋予写入权限。清除浏览器缓存后重试，有时候是缓存导致的页面显示问题。

## 基础配置

### 站点配置

安装完成后，首先需要配置站点基本信息。登录后台管理系统后，找到网站配置菜单，可以修改网站名称、网站标题、关键字、描述等 SEO 相关内容。这些信息会影响搜索引擎收录和社交分享时的显示效果，建议根据实际需求认真填写。

网站 Logo 等静态资源配置位于 public/static/images 目录下。将准备好的 Logo 图片替换同名文件即可。需要注意 Logo 的推荐尺寸和文件格式，通常使用 PNG 或 SVG 格式，分辨率为 200x60 像素左右较为合适。修改网站图标（favicon）需要替换 public/favicon.ico 文件，建议使用 16x16、32x32、48x48 等多种尺寸的图标合并为一个 ICO 文件。

### 后台登录

访问后台管理地址通常是 你的域名/admin 或 你的域名/admin/login。使用安装时创建的管理员账号登录后台管理系统。首次登录后，建议立即修改默认密码，使用包含大小写字母、数字和特殊字符的强密码。定期更换密码也是良好的安全习惯。

后台首页（控制台）展示了系统概览信息，包括用户统计、访问趋势等数据。左侧导航栏包含所有管理功能的入口。顶部工具栏提供了快捷操作入口，如清除缓存、刷新菜单等常用功能。页面右下角可能显示框架和版本的版权信息。

### 缓存管理

框架运行过程中会在 runtime 目录下生成各种缓存文件，包括编译后的模板文件、配置缓存、数据缓存等。修改配置文件或模板文件后，有时需要清除缓存使修改生效。清除缓存的最直接方法是手动删除 runtime 目录下对应应用的所有文件。在后台管理中也可以找到清除缓存的入口，点击后系统会自动清理缓存文件。

调试模式下，系统会在页面底部显示调试信息栏，包含加载时间、内存占用、数据库查询次数和详情等信息。开启调试模式的方法是修改 config/app.php 配置文件，将 debug 选项设置为 true。调试模式会影响页面加载性能和安全性，生产环境务必关闭调试模式。

## 目录结构

### 应用目录详解

一鱼快速构架的代码组织遵循 MVC 架构模式，各层代码分离明确。app 目录是应用代码的核心区域，包含多个独立的应用模块，每个应用模块都有自己完整的 MVC 结构。理解各目录的职责有助于更好地进行开发工作。

admin 目录是后台管理应用，包含系统的管理功能模块。controller 子目录存放所有控制器文件，如 User.php 处理用户管理、Menu.php 处理菜单管理、Config.php 处理系统配置。model 子目录存放数据模型文件，如 User.php 定义用户数据操作、Menu.php 定义菜单数据操作。view 子目录存放视图模板文件，与控制器对应组织为子目录结构，public 子目录存放公共模板如头部、底部、侧边栏等。

index 目录是前台应用模块，包含面向终端用户的功能。controller 中的 Index.php 处理首页展示，User.php 处理用户登录注册等操作。install 目录是安装应用模块，仅在系统未安装时访问，包含引导用户完成初始配置的控制器和视图。

### 配置文件说明

config 目录集中管理系统的所有配置文件，每个配置文件控制框架或应用的特定功能模块。database.php 定义数据库连接参数，包括服务器地址、端口号、数据库名称、用户名密码等。route.php 定义 URL 路由规则，包括默认控制器和方法、URL 后缀、路由别名等配置。template.php 定义模板引擎的行为，包括左右定界符、编译缓存路径等配置。

cache.php 配置缓存行为，包括缓存类型、缓存路径、缓存有效期等。session.php 配置会话管理，包括会话存储方式、会话生命周期等。middleware.php 配置中间件，包括全局中间件和应用级中间件的注册。upload.php 配置文件上传功能，包括允许的文件类型、文件大小限制、上传路径等。

### 框架核心目录

xphp 目录包含框架的核心代码，通常不需要开发者修改。core 子目录包含框架的核心类文件，App.php 是应用入口类，负责协调各组件工作；Model.php 是模型基类，封装了数据库操作的基本方法；Controller.php 是控制器基类，提供视图渲染、页面跳转等基础方法；Request.php 封装请求处理逻辑；Response.php 封装响应输出逻辑。

cli 子目录包含命令行工具的实现代码，Make.php 是代码生成器的主类，Command.php 是命令行命令的基类。function.php 和 helper.php 包含框架的全局函数，如 view()、url()、session() 等助手函数，开发者可以在此添加自定义的全局函数。

## 代码生成

### 生成模型

代码生成器是框架提高开发效率的核心工具，通过简单的命令即可生成完整的 CRUD 代码。首先需要确认目标数据表已经存在，如果数据表不存在，可以使用 SQL 语句或数据库工具创建。

生成模型的基本命令是 php xphpcli make:model 应用名@模型名。例如，生成后台应用的用户模型，执行 php xphpcli make:model admin@user。命令执行后会在 app/admin/model/ 目录下生成 User.php 模型文件。生成的模型文件包含基本的表名配置、主键配置，以及常用的增删改查方法示例。

生成带验证规则的模型可以使用 php xphpcli make:model admin@user id _def -f 命令，其中 id 指定主键字段名，_def 指定使用默认模板，-f 参数表示强制覆盖已存在的文件。生成的模型中会自动包含字段验证规则、数据自动完成等配置代码。

### 生成控制器

控制器是请求处理的入口，生成控制器的基本命令是 php xphpcli make:ctrl 应用名@控制器名。执行 php xphpcli make:ctrl admin@user 命令会在 app/admin/controller/ 目录下生成 User.php 控制器文件。生成的控制器包含 index（列表）、add（新增）、edit（编辑）、delete（删除）等标准方法。

控制器方法与视图文件存在对应关系，index 方法对应列表页面，add 方法对应新增页面，edit 方法对应编辑页面。这些方法的代码已经包含基本的权限检查、数据验证、视图渲染等逻辑，可以直接使用或根据业务需求进行修改。

### 生成视图

视图文件是页面的模板，生成视图的命令格式是 php xphpcli make:view 应用名@控制器名 方法名。例如，生成用户控制器的列表视图，执行 php xphpcli make:view admin@user index 命令。生成的视图文件位于 app/admin/view/user/ 目录下。

视图模板包含 Bootstrap 风格的 HTML 结构，已经配置好表格、表单、分页等常用元素。可以直接修改生成的 HTML 代码添加业务需要的字段和元素。生成多个方法的视图可以使用空格分隔，如 php xphpcli make:view admin@user index add edit 会同时生成列表、新增、编辑三个视图。

### 一键生成

对于新建的数据表，可以使用代码生成器一键生成完整的 MVC 代码。首先确保数据库中有目标数据表，然后按照以下顺序执行生成命令：先生成模型，再生成控制器，最后生成视图。生成完成后需要手动注册菜单才能在后台访问。

注册的菜单信息需要在后台的菜单管理中添加，或者在数据库的菜单表中插入记录。菜单的 href 字段格式为控制器名/方法名，如 user/index、user/add 等。配置好菜单后，清除缓存并刷新后台页面，新添加的功能菜单即可显示并访问。

## 常见问题排查

### 页面404错误

访问任何页面都显示 404 错误是最常见的问题之一，通常是伪静态配置未生效导致。检查 Nginx 或 Apache 的伪静态规则是否正确添加并生效。确认网站运行目录是否指向 public 目录，网站目录错误指向项目根目录会导致无法访问。清除浏览器缓存后重试，某些情况下是浏览器缓存了旧的错误页面。

### 数据库连接失败

数据库连接失败时会看到相应的错误提示。首先确认数据库服务是否正在运行，MySQL 服务停止会导致连接失败。使用正确的用户名和密码登录 phpMyAdmin 或命令行工具，验证数据库凭据是否正确。检查防火墙设置，确保数据库端口（默认 3306）未被阻止。

### 页面显示空白

页面完全空白通常表示发生了 PHP 错误但错误显示被关闭。开启调试模式查看具体错误信息，修改 config/app.php 中的 debug 配置为 true。检查 runtime 目录是否存在且有写入权限，缓存写入失败可能导致页面空白。确认 PHP 版本符合要求，PHP 版本过低或过高可能导致兼容性问题。

### 配置修改不生效

修改配置文件后刷新页面没有看到效果，是因为框架缓存了配置内容。必须清除 runtime 目录下对应应用的缓存文件才能使新配置生效。执行后台的清除缓存功能，或者手动删除 runtime 目录下的缓存文件后重试。

## 部署清单

### 开发环境转生产环境

开发完成后，将项目部署到生产环境需要关注以下要点。首先确认所有代码已完成开发和测试，功能符合预期，暂无遗留问题。其次检查敏感信息的安全处理，生产环境的数据库密码、加密密钥等敏感信息应使用环境变量或独立的配置文件管理，禁止硬编码在代码中。

关闭调试模式是部署前必须完成的事项，修改 config/app.php 将 debug 设置为 false。开启调试模式会暴露系统路径、错误详情等敏感信息，带来安全隐患。配置生产环境的错误日志，将错误信息记录到日志文件而不是直接输出到页面。

### 服务器配置优化

生产环境建议使用 HTTPS 加密传输，保护用户数据安全。可以使用 Let's Encrypt 等机构提供的免费 SSL 证书。配置 Web 服务器的静态资源缓存，减少重复请求，提升页面加载速度。Nginx 配置示例在响应头中添加缓存控制信息：

```nginx
location ~* \.(css|js|jpg|jpeg|png|gif|ico|woff|woff2)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

### 备份策略

建立完善的备份机制是保障数据安全的重要措施。数据库应定期备份，建议每天执行一次全量备份。文件备份包括用户上传的文件和系统配置文件。备份文件应存储在与服务器分离的位置，防止单点故障导致备份丢失。可以编写自动化脚本配合服务器定时任务实现无人值守备份。
